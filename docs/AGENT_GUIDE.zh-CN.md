# 智能体指南

这份指南供帮助用户安装、启动和使用 Story Room 的智能体阅读。前半部分给出从仓库链接到开始写作的流程；后半部分保留修复问题与代码维护所需的入口和合同。

它是公开项目说明，不替代仓库根目录的 [`AGENTS.md`](../AGENTS.md)。`AGENTS.md` 里的安全、数据、协作和发布规则是硬规则；本指南只补充功能事实、代码地图和验证入口。代码和测试发生变化时，应以当前代码、测试和适用规则重新核对本页，不能把旧文档当作实现承诺。

其他尚未提供简体中文版本的资料以英文为准。

## 帮用户安装、启动与使用

用户只给仓库链接、希望开始使用时，默认执行本地安装与启动：自行识别系统和已有环境，获取源码、安装依赖、启动并打开网页，再指导连接模型和写作。不要求用户选择运行版本或先体验示例。只有缺失信息会影响已有数据或无法自行查明时才询问；用户明确要求审查或开发时，按其实际请求处理。

### 1. 核对现有环境

检查操作系统、当前 shell、目标目录以及 `node --version`、`npm --version`。要求 Node **22.x 中的 22.18.0 及以上，或 24.x**，对应 `package.json` 的 `^22.18.0 || ^24.0.0`；其他主版本不在当前声明范围内。

已有安装先确认启动方式、工作区改动和使用的书库目录，复用现有安装。不要读取密钥配置的正文，不要覆盖 `.data/`、配置或未提交文件。环境缺失时说明需要安装的组件和目标版本，在用户授权范围内处理，不擅自改变系统默认运行时。

### 2. 获取源码并启动本地服务

首次获取可用以下命令；这些不含环境变量赋值的命令同时适用于 PowerShell 和常用 POSIX shell：

```bash
git clone https://github.com/beniedev/story-room.git
cd story-room
npm ci
```

已有源码从相应目录开始；ZIP 下载无需 Git，解压后运行 `npm ci`。若仓库访问失败，说明访问状态，不索取用户的 GitHub 凭据。`package.json` 中的 `private: true` 是 npm 发布保护，不代表 GitHub 可见性。

在项目目录运行 `npm run dev`，同时启动本地 API 和页面。默认打开 **http://127.0.0.1:4310**。Agent 应完成启动、核验与打开网页，不只把命令交回用户。

说明终端需要保持运行，`Ctrl+C` 停止。再次打开时，回到原目录重新运行 `npm run dev`。安装不需要建立后台服务；如 Agent 使用后台进程保持运行，应记录自己启动的进程和停止方式，不结束其他进程。

默认使用回环地址。用户需要受信任网络内的其他设备访问时，才解释 `npm run dev -- --host 0.0.0.0`：其他设备使用运行服务的电脑地址，而不是 `0.0.0.0` 或自己的 `localhost`。能访问该服务的设备可以使用它。普通安装不包含公开部署、后台服务安装或新增产品访问步骤。

### 3. 验证启动结果

先检查启动进程和错误，再打开实际页面。新本地安装可以检查同源的 `GET /api/health` 返回 JSON `{"ok":true}`；默认地址是 `http://127.0.0.1:4310/api/health`。

还要检查页面的 JavaScript/CSS 能加载、书架能显示，以及“设置 → 保存位置”对应预期运行方式。首页 HTTP 200、进程已启动、单元测试通过与实际使用成功应分别报告。

不要用真实书稿做安装测试。安装验证可以用合成内容新建一本明确标为测试用途的书；在已有书库操作前先说明会新增什么，由用户选择合适的书目。

### 4. 连接用户的 AI 服务

引导用户在本地服务模式的“设置 → 模型连接”填写可信服务的 URL、模型 ID 和密钥。密钥由用户在界面输入，不要求粘贴到对话中，不读取或输出密钥文件。发起真实生成前，说明所选写作材料会发给该服务；只有用户授权了该调用才继续。

填写后点“保存连接方案”；成功回调会自动选中已保存的方案。“模型连接”标题下与正文顶部显示当前方案及模型，可据此核对。已有方案通过“连接方案”下拉框切换，有未保存修改时先处理界面提示。“测试”不保存方案，也不能替代真实生成核验。

“测试”验证 `/models` 的连通性，以及返回列表时的模型匹配，不代表 `/chat/completions` 的生成参数兼容。初始内置测试连接不是真实模型服务；不要用其输出宣称真实 AI 已可用。缺少服务信息时，完成安装后明确指出待用户在本机填写的字段，不把测试模式作为替代交付。排障只收集去除凭据和书稿的错误形状，不复制原始请求或配置。

### 5. 带用户完成第一次写作与备份

1. 点“新建书目”并确认，新书自带一个章节和小节。在已经选好真实连接后，打开小节，指导用户输入文字并“发送并续写”。是否发送及使用哪份文字由用户决定。
2. 在“本书设定”解释资料如何加载：写作风格与剧情大纲编辑后“保存并加载”；角色卡和世界观另有加载范围，选好章节、小节后确认载入。
3. “选择前文”处理较早小节的梗概引用，不是角色卡或世界观的设置入口。梗概和勾选需要“保存并加载梗概”确认。
4. 在书架用“导出当前书目”选择 JSON，随后通过“导入 JSON 备份”恢复副本。核对副本可打开、原书仍在；不要仅以文件下载成功认定恢复已通过。
5. 说明已保存书目、会话恢复草稿、尚未提交的输入框内容是不同状态。编辑框里的文字不一定在 JSON 中，遇到冲突先另行保留这些文字，再导出书目、决定是否重新载入。

更详细的操作见[中文使用手册](USER_GUIDE.zh-CN.md)。应用界面当前为中文；使用英文解释时，保留中文按钮名或提供对应表。

### 6. 常见问题先这样排查

| 现象 | 检查与处理 |
| --- | --- |
| 端口被占用 | 确认占用者是否为已有 Story Room；复用它或停止本任务自己启动的进程，不结束不明进程。API 端口由 `STORY_API_PORT` 控制，开发前端端口见 `vite.config.ts`，不要假设一个 `PORT` 会同时修改两者。 |
| 页面打不开或空白 | 核对运行命令、地址、进程错误和静态资源响应。构建更新后重新启动对应预览，再检查页面；HTML 返回成功不证明 JS/CSS 正确。 |
| 换浏览器后看不到书或无法真实生成 | 检查访问地址、实际保存位置和所选模型连接；不能仅凭症状断定原因。先定位原书库并保护内容，不创建空库替代或擅自清理浏览器数据。 |
| 保存冲突 | 保留未提交文字，导出当前 Book，再由用户决定重新载入与手动采用内容。不要覆盖新版本或清空存储。 |
| 模型测试成功但生成失败 | 区分模型发现与生成；检查脱敏后的错误、所选连接和参数，不把失败直接归因于密钥或自动改服务地址。 |

排障不能以删除 `.data/`、清空浏览器站点数据或覆盖现有配置作为默认修复。多个标签页均可编辑，用户不需要管理“哪一页拥有编辑权”。

## 运行模型和不变量

### 书目是隔离边界

`Book`（书目）是资料和正文的最小隔离单元。角色卡、世界观、剧情大纲、小节梗概、候选版本和正文文本只能来自当前书目。切换书目、导入 JSON、生成上下文和导出时都要保持这个边界，不能以“方便上下文”之类的理由跨书读取或拼接。

### 两种写作模式共用一条管线

作者模式和角色模式共用保存、上下文计划、模型服务请求和应用生成结果的流程。角色模式只收窄本轮可用的角色视角和权限；不要为角色模式另造一套持久化或提示发送路径。正文保持连续小说排版，用户输入和模型输出的块结构是编辑辅助数据，不是聊天气泡或消息时间线。

### 上下文是显式选择的

`contextPlan.ts` 计算本轮可能发送给模型服务的资料和纳入原因。前文引用由用户确认；小节梗概必须是可用且新鲜的记忆，模型生成的草稿在确认前不能进入普通续写。上下文令牌估算用于预览和提示，不能冒充模型服务的实际限制，也不应被实现成武断的应用级长度上限。

`packetFor` 包含当前书名、章名、小节标题与位置；选中且符合条件的 `Section.memory` 会作为前文引用发送。旧 `Book.summaries`／`Book.canonFacts` 不作为当前规划器的资料源，不能据此宣称所有梗概都留在本机。

### 本地服务模式与浏览器模式

| 运行方式 | 保存和生成 | 维护时要记住 |
| --- | --- | --- |
| `local-host`（本地服务模式） | 书目写入可读文件；内置示例服务（Fake）或配置的 OpenAI 兼容模型服务 | 模型服务密钥与书目分开保存；保存请求按版本校验并串行处理 |
| `hosted/device`（浏览器模式） | 书目保存在 localStorage，恢复草稿按标签页保存；生成仍使用示例服务 | 存储未加密；写入自动互斥，旧版本保存被拒绝 |

浏览器页面始终可编辑。初始化、创建、删除、导入和保存共用 `withDeviceLibraryWrite`，在获得协调后才读取当前版本并同步写入 Book 与索引。Web Locks 可用时按操作获取并自动释放；IndexedDB 可用时也以 readwrite 事务协调，因此没有 Web Locks 的页面仍可正常保存。协调失败必须报错，不得无锁重放写入。IndexedDB 不存放书稿。

恢复草稿使用每页独立的 `sessionStorage`，刷新可恢复，关闭标签页会结束会话；Book 仍保存在 `localStorage`。旧共享草稿在写入协调范围内先复制到当前页，成功后才移除旧键。其他标签页不能清除或覆盖本页草稿。成功保存旧 revision 时只推进已保存版本和草稿基线，不替换较新的页面编辑。

以上仅协调同一浏览器存储区域，不包含跨设备同步或本地服务进程间协调。

## 常见维护任务

### 改文案或一个控件

先在 `src/App.tsx` 和对应组件用 `rg` 搜索现有中文标签，再改最靠近实际渲染的位置。确认 aria label、title、状态提示和确认框描述没有互相矛盾。用户指南只记录真实标签，不要为方便说明臆造操作路径。

### 增加或修改书目数据

从 `src/types.ts` 开始，随后检查：

1. `normalizeBook` 及相关领域辅助函数是否能读取旧书目。
2. `bookImport.ts` 是否校验和恢复该字段。
3. `bookExport.ts` 是否保留需要备份的内容。
4. `server/store.ts`、`deviceLibrary.ts` 和 App 的同一保存流程是否都能写回。
5. 当前书目切换、冲突、候选和前文引用是否仍保持书目隔离。
6. 添加一个能证明真实行为的窄测试，再按规则运行完整验证。

不要在组件里直接 `localStorage.setItem` 或另造一条只保存半本书目的捷径。普通书目变化、资料确认、候选采用和前文引用都应沿用现有的完整保存管线。应用没有为了正文长度、候选数量或小节梗概项目数设置武断上限；模型服务的实际上下文和输出限制由配置决定。

### 改上下文或生成

先阅读 `contextPlan.ts`、`generationRequests.ts` 和相关测试，确定请求的唯一目标、来源范围和候选来源签名。同步检查 `ContextCompositionDrawer` 的可见摘要：它必须与实际纳入原因大致一致，但不能显示原始模型服务消息或隐藏推理。

变更资料加载时，要保持这些事实：剧情大纲是未来指导；`continue-section` 请求优先使用 `authorNote`，其他正文生成请求使用当前 `section.note`；非空小节注释以原文作为末尾 assistant 消息发送，空白注释不发送；应用不会把注释写入正文块或自动拼到生成结果后面；小节梗概需要新鲜且已确认；用户没有确认的前文选择不能写入书目。作者模式和角色模式都应经过同一保存、上下文、模型服务和应用结果管线。

生成结果可以带 `finishReason`。`stop` 按正常流程应用；`length`、`content-filter`、`refusal` 和 `unsupported` 对应的草稿应可复制，但不能应用到正文、替换候选或保存为梗概。缺失或 `unknown` 按普通结果流程应用，并提示服务没有提供明确结束原因。只根据结构化字段判断，不从草稿措辞猜测；迟到结果仍须检查请求目标和 Book 会话。

### 改模型服务或 API 密钥

入口通常是 `src/providerProfiles.ts`、`src/api.ts`、`src/components/ProviderSettings.tsx` 和 `server/providers.ts`。先区分本地服务模式与浏览器模式：

- 本地服务模式可以保存示例服务或 OpenAI 兼容连接方案；密钥在独立的模型服务配置中按现有规则处理，不进入书目、JSON、合成测试样例、日志或错误文本。
- 浏览器模式的生成仍是示例服务；连接测试可以临时把密钥发到填写的 `/models` URL，页面脚本在运行期间可读取，应用不持久化它。
- “测试成功”只表示 `/models` 可达，并在有列表时找到模型 ID；它不是 `/chat/completions` 参数兼容性证明。
- 模型服务实际收到的材料由上下文计划决定；修改接口时不能绕过书目隔离或向界面回显原始内部消息。

### 改小节梗概或前文选择

从 `sectionMemory.ts` 的草稿、新鲜度、来源和上一快照语义开始，再看 `ContextToolsDrawer.tsx` 与 App 的生成/确认回调。生成的 `model-draft` 先停在页面编辑草稿，只有用户确认“保存并加载梗概”后才成为可用的小节梗概和上下文引用。正文改动后应按内容指纹重新判断新鲜度，而不是无条件沿用旧梗概。

抽屉草稿由 App 持有的会话 Map 按书目和目标小节隔离，不进入浏览器长期存储。点击外部空白或关闭抽屉不会清稿，也不会应用修改；相关前文名称下的红字标明未保存状态，确认保存成功后消失。迟到生成结果需要同时核对会话身份和请求代次；删除目标后不能复活草稿。所有会话的待确认修改都应计入离页提醒。

目录拖动排序只改变作品顺序。六点把手只在目录多选模式显示，支持鼠标或触屏拖动。`getDirectoryMoveImpact` 比较顺序导致的前文资格变化，不重新生成梗概，也不承诺过期梗概已经可用。`contextReferences.ts` 在保存前文选择时保留尚被用户选中的既有当前／未来引用，禁止用这一入口新增未来引用。移动撤销只记录逆向位置，应用到最新书目；不要回放整本旧书覆盖后续正文。

角色卡和世界观设定列表在多选模式下支持单项六点把手拖动排序。两个列表共用 [`src/components/SourceList.tsx`](../src/components/SourceList.tsx)；每次移动由 `src/sourceSelection.ts` 的 `moveSourceItem` 计算，再由 `Bookshelf.onBookChange` 接入原有书目保存链。把手支持鼠标或触屏拖动；聚焦后按上、下方向键可逐项移动，拖动进行中按 Esc 可取消。单项在各自列表内拖动后会自动保存新顺序；不支持整组选中内容拖动，也没有“撤销”。

### 改浏览器模式保存协调

先看 `deviceWriterLease.ts`、`deviceLibrary.ts`、App 的保存队列和存储事件。每个 Book／索引写入入口都必须在同一个短临界区中重新检查版本；App 回调不得在返回后再次直写持久 Book。草稿只写当前标签页，导出无写入副作用。不要恢复页面独占、接管按钮、轮询或强制抢锁。

回归应覆盖真实多标签并发写入、初始化／创建／删除／导入与保存交错、同书版本冲突及各页刷新恢复。带引用的目录移动必须经过真实磁盘保存、JSON 导入与撤销；暂时位于后方的引用可存储，模型前文仍严格排除当前和未来小节。

## 用合成数据复现问题

复现和测试优先使用仓库已有的中性样例：`createExampleBooks()`、`createLegacyFixtureBook()`、书目导入导出辅助函数，以及 `tests/helpers/fakeDeviceLocks.ts`。自己写合成测试样例时使用虚构的书名、角色、章节和内容；不要复制用户作品、真实姓名、账号、设备名、地址、端点或密钥。

按当前问题选择相关场景即可，不必每次都覆盖整套流程。可选的最小场景包括：

- 生成、候选或正文问题：用示例服务建一本只有一章和两三个小节的书目，覆盖问题涉及的作者/角色模式、空正文、最后一块用户输入、多个候选或取消生成。
- 资料和上下文问题：只使用当前书目的角色卡和世界观，检查确认前后 `contextReferences` 和可见上下文摘要的变化。
- 导入导出问题：用完整 JSON 的内存字符串，确认导入生成新 ID 且不覆盖原书目。
- 浏览器模式并发问题：使用独立测试存储与真实多标签页验证并发写入、旧版本和草稿隔离。
- 模型服务问题：使用假的响应或示例服务；不要向真实端点发送密钥。

这样得到的案例既能复现行为，也能安全放进公开测试和问题报告。若问题只在真实模型服务或特定浏览器发生，要记录抽象后的能力和错误形状，不要把凭据、完整请求、原始私密日志或用户书稿带进仓库。

## 快速排查表

| 现象 | 先查哪里 | 正确的用户解释 |
| --- | --- | --- |
| 浏览器模式保存失败 | 保存协调器、浏览器存储、当前书目版本 | 保留本页编辑，显示实际错误并允许 JSON 导出；不要求用户管理编辑权 |
| 修改后没有马上出现 | App 自动保存状态、`updatedAt`、保存队列和`storage` 事件 | 先看状态提示；冲突时导出 JSON，再显式重新载入，不自动合并 |
| 模型回答似乎重复用户输入 | `generationRequests.ts` 的 `respond-to-input` 路径和 Writer 的“生成回答” | 末尾用户块下的操作会生成回答，不会复制那段输入 |
| 梗概改了但生成没变化 | `ContextToolsDrawer.tsx` 的确认流程、小节梗概新鲜度和 `contextReferences` | 先确认“保存并加载梗概”；关闭前文抽屉而不确认不会生效 |
| 模型服务测试成功但生成失败 | `/models` 测试语义、模型服务实现和实际 `/chat/completions` 响应 | 测试只证明模型发现或连通，不证明完整生成兼容 |

遇到未覆盖的行为，先保留证据和最小合成复现，再回到事实来源顺序；不要用猜测性的成功提示或文档措辞掩盖未知状态。

## 本地运行与 API 细节

以下信息供安装排障和接口维护使用。普通用户通过设置和现有启动脚本即可写作。维护者可用 `npm run build:local` 加 `npm run server` 验证构建后的本地服务，默认访问 `http://127.0.0.1:4311`；这不需要用户选择另一个版本。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `STORY_DATA_DIR` | `.data/` | 本地书库根目录 |
| `STORY_PROVIDER_CONFIG` | `.data/private/providers.json` | 独立的模型服务配置文件，可能包含明文密钥 |
| `STORY_API_PORT` | `4311` | 本地 API 端口；开发模式的 Vite 代理读取同一个值 |
| `STORY_HOST` | `127.0.0.1` | `npm run server` 的监听地址；`npm run dev` 用 `--host` 参数设置它 |
| `STORY_STATIC_DIR` | `dist-local` | `npm run server` 提供的静态文件目录 |

路径相对启动工作目录解析。`STORY_DATA_DIR` 与 `STORY_PROVIDER_CONFIG` 独立，不会互相改写或搬迁数据。`scripts/dev.mjs` 会读取项目的 `.env.local`；直接 `npm run server` 不会读取该文件，需要由启动环境提供变量。PowerShell 使用 `$env:NAME = 'value'`，POSIX shell 可用 `NAME=value command`；先核对启动方式再给用户相应命令，不读取或输出密钥值。

本地模型密钥文件按明文处理；POSIX 写入权限为 `0600`，Windows 文件权限不能视为等价凭据存储。改变已保存连接的 `endpoint` 或 `kind` 需要重新输入密钥。HTTP/HTTPS 的用户配置服务可位于公网、回环、局域网或私有网络；元数据地址、链路本地地址和重定向仍被拒绝。

`POST /api/context-plan` 返回紧凑预览；`POST /api/generate` 返回草稿、可选的 `finishReason` 和候选来源签名，不回显内部消息。生成请求可指定布尔值 `stream`：开启后响应为 `application/x-ndjson`，按行发送 `{"type":"delta","text":"…"}`，最后发送带普通结果的 `{"type":"result","result":{…}}`，或带错误信息的 `{"type":"error","error":"…"}`。最终 `result` 表示生成响应结束；草稿是否可以应用由 `finishReason` 判断，中途断流不算完整响应。未启用流式时仍返回 JSON。小节梗概等待完整结构化结果，不使用正文的流式显示。

保存仍传输、校验整个 Book，并使用 `updatedAt` 比较已保存版本。相同版本的重复保存复用结果；本地服务跳过内容未变化的来源和正文文件重写。应用不为正文、候选、请求或响应设置武断上限，大书仍需要更多内存和 I/O。模型上下文与输出设置接受正的安全整数，实际可用范围取决于服务；上下文估算是提示，不会阻止生成。[增量保存 API](INCREMENTAL_SAVE.md) 尚未实现。
