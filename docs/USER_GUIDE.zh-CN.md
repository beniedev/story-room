# 使用手册

欢迎来到 Story Room（故事书屋）！它把正文、角色、世界观和写作提示放在同一本书里，让你可以安静地写连续小说，也可以在需要时请 AI 接着写几段。下面的按钮名称以当前中文界面为准；功能仍处于 Alpha 阶段，重要作品请保留一份 JSON 备份。

## 安装与打开

把 https://github.com/beniedev/story-room 交给能操作本机的 Agent，它可以按[安装指南](AGENT_GUIDE.zh-CN.md)检查环境、安装并打开应用。你不需要选择运行版本。安装好后，在“设置 → 模型连接”填写可信服务的 URL、模型 ID 和 API Key，选好连接，再开始写作。密钥在本机界面输入，不必发送到聊天中。

<details>
<summary>自己安装、停止与再次打开</summary>

准备 Node.js **22.x（至少 22.18.0）或 24.x** 和 npm。用 Git 获取代码后运行：

```bash
git clone https://github.com/beniedev/story-room.git
cd story-room
npm ci
npm run dev
```

也可以下载 ZIP、解压，在项目目录从 `npm ci` 开始。以上命令适用于 PowerShell 和常用 macOS/Linux 终端。保持终端运行，打开 **http://127.0.0.1:4310**。按 `Ctrl+C` 停止；下次回到同一目录运行 `npm run dev`，不需要每次重新安装。

</details>

“设置 → 保存位置”显示书库位置，默认是运行服务电脑上的 `.data/`。从受信任网络中的其他设备访问时，书稿仍在那台电脑上。需要配置网络访问或更换书库路径时，让 Agent 按[本地运行说明](AGENT_GUIDE.zh-CN.md#本地运行与-api-细节)处理，保留原书库和配置；应用不会自动搬迁文件。

## 从书架开始

### 新建、切换和导入书目

1. 点“新建书目”，填写“书名”，选择“确认新建”。新书会成为当前书目。
2. 用“切换书目”在现有书之间切换。
3. 点“导入 JSON 备份”，选择以前导出的 JSON 文件。导入会建立一个恢复副本，并显示类似“已导入《…》的恢复副本，原书目未覆盖”的提示；原书不会被覆盖。
4. 点“导出当前书目”，可以选择 EPUB 电子书、Markdown 文档、TXT 纯文字或 JSON 完整备份。EPUB、Markdown、TXT 适合阅读或继续编辑；JSON 会保留角色卡、设定、加载范围、正文结构、候选版本和梗概历史。

书架里的“管理当前书目”菜单可以“修改书名”或“删除书目”，删除前会有确认提示。书库可以为空；删除最后一本后，可以用“新建书目”或“导入 JSON 备份”重新开始。要删除章节或小节，请点顶部“整理目录”，勾选后再点“删除所选内容”。这类删除请先导出备份。

### 章节和小节

一本书由章节和小节组成：

1. 在书架工具栏点“新建章节”，填写“章节名称”。
2. 在章节行末尾点“新建小节”按钮，填写小节名称。
3. 点击小节行中标题以外的区域，立即打开正文；点击章节行中标题以外的区域，展开或收起章节。每个小节显示字数和估算 token 数，便于了解规模。
4. 单击或轻点小节标题可进入正文，章节标题则展开或收起该章；标题会等待 300 毫秒，以便快速双击或双点时只在原处改名。行内其他区域仍立即进入或展开。键盘聚焦目录标题后，Enter、空格执行主动作，F2 直接改名。

改名时只显示输入框：点编辑区域以外，有修改就保存，没有修改就退出。也可以按 Enter 保存、Esc 恢复原名。中文输入法确认候选字时不会提交。空白名称和保存失败会在原处提示，并保留输入供修改或重试。章节右侧的小箭头会随展开、收起改变方向。

正文按连续小说排版保存。用户输入和 AI 输出在内部以块记录，界面仍把它们呈现为一篇可以继续阅读的正文，不是聊天气泡或群聊时间线。

### 整理目录

在普通目录中，章节行只有“新建小节”按钮，小节行只有进入箭头。改名可快速双击或双点标题，或聚焦后按 F2。点顶部“整理目录”进入多选，再点同一位置的“×”退出。删除按钮只在多选时出现，选中章节或小节后才能使用。

点目录顶部的“整理目录”可以勾选并批量删除。整理模式下才显示六点拖动把手，可用鼠标或触屏调整章节顺序、小节在章内的顺序，或把小节移到另一章。空章也能接收小节。

移动保存成功后，可以“撤销”最近一次移动。撤销只恢复位置，期间新写的正文和改名会保留。保存失败时，目录保持原来的顺序，你可以重试。

目录顺序也是故事的先后顺序。如果移动会让已有前文引用变成后文，界面会提示受影响的小节；引用记录仍然保留，但暂不加载。移回前面后会重新具备前文资格，梗概仍须满足已确认和未过期等条件。点“完成整理目录”回到普通目录。

## 先把书的资料放好

在书架点“本书设定”，可以管理只属于当前书目的资料。一本书的角色、世界观、剧情和正文不会自动混入另一本书。

### 剧情大纲和写作指导

“全局指引”下有“写作风格指导”和“剧情大纲”：

- “写作风格指导”可以写语气、叙述方式、语言习惯等。
- “剧情大纲”可以写较长期的情节方向。

编辑后点“保存并加载”，再在确认框点“确认保存并加载”。确认前的修改只是页面草稿；保存后，资料会按当前书的加载范围进入后续生成。剧情大纲会作为未来方向参与正常续写和“再生成一版”。

### 角色卡和世界观设定

在“角色卡”或“世界观设定”下点“新建角色卡”或“新建世界观设定”。角色卡可以填写“角色名”“角色要点”“角色设定”；世界观设定可以填写“设定名称”和“设定内容”。

点各列表的“选择”进入多选，点同一位置的“×”退出。删除按钮只在多选时出现，选中资料后才能使用；删除前会再次确认。

多选模式下，角色卡和世界观设定列表中的每项也会显示六点拖动把手。拖动单项可在各自列表内调整顺序，顺序会自动保存；把手支持鼠标或触屏拖动，聚焦后按上、下方向键可逐项移动，拖动进行中按 Esc 可取消。不支持整组选中内容一起拖动，也没有“撤销”。

每份资料旁边都有加载范围入口：

1. 点“加载角色卡”或“加载世界观设定”。
2. 在“加载角色卡”或“加载世界观设定”页面勾选需要使用它的章节小节，也可以点“全选”。
3. 点确认图标，在确认框中完成“确认载入”。

没有勾选的小节不会加载这份资料。加载范围本身也是书目数据的一部分，会随 JSON 完整备份保存。

## 在正文页写作

打开一个小节后，会进入正文编辑页。顶部可以使用：

- “本书设定”：返回查看或编辑当前书的资料。
- “选择前文”：选择本小节生成时要参考的前文梗概。
- “设置”：调整显示、流式输出和模型连接。

工具栏下方的章名和节名也支持双击、双点或键盘原地改名，保存方式与目录一致。

### 作者模式和角色模式

底部的“写作操作”菜单有两种模式：

- “作者模式 · 写作接龙”：由你决定叙事方向，AI 从当前正文继续写。
- “角色模式 · 第一视角”：先选择“扮演角色”，再用该角色的第一人称行动、台词或选择来推进场景。AI 负责世界和其他角色，角色模式会收窄本轮生成的视角与权限。

角色模式必须先选本书角色；没有选角色时，页面会提示“角色模式需要先选择本书角色，选择后才能发送”。两种模式共用同一套保存、上下文、模型服务和应用结果流程。

在“写作操作”里还可以编辑“小节注释”。它适合写“跳过路程，直接写抵达后的重逢……”一类对当前小节的指导，不会直接进入正文；修改后会保留，并在作者模式和扮演模式中生效。

### 编辑正文块

点正文中的一块即可选中：

- 用户输入可以“编辑”或“删除”。
- AI 输出可以“编辑”“删除”或“再生成一版”。
- 编辑页会显示“编辑用户输入”或“编辑 AI 输出”，完成后点“完成”；改动会走和普通正文一样的自动保存流程。
- 如果选中的 AI 输出有多个候选，删除时可以选择保留某一版，也可以删除整段及全部候选。

正文仍按连续段落阅读。块只是帮助你定位输入、回答和候选版本，不会把小说变成聊天记录。

双击正文可以用浏览器选词；拖选文字或长按复制时，不会顺带选择正文块。想明确选择一块时，也可以用旁边的片段选择控件，键盘同样能操作。

## 生成、再生成和候选版本

在底部输入框写下想让 AI 接着处理的文字，点“发送并续写”。作者模式的提示是“写下一段正文，让 AI 从这里接着写……”；角色模式会提示输入行动、台词或选择。

如果当前小节最后已经有一块用户输入，下面会出现“生成回答”。点它会为那一块生成回答，不会把同一段用户输入再复制一次。

对已存在的 AI 输出使用“再生成一版”时，新的候选会根据该回答之前、当前已采用的正文来生成；目标回答本身、它的旧候选和后面的正文不会被偷偷塞进这次请求。生成成功后，新版本会自动成为当前版本，并显示“已生成新的回答，并已切换到当前版本”。

有多个版本时，候选栏会显示“浏览 AI 回答候选”、版本计数和“上一版”“下一版”。左右箭头会立即切换当前采用的版本并自动保存，它们不会再次调用 AI。当前采用的版本会用于后续生成、普通导出和梗概新鲜度判断。

候选会和书目一起保存，刷新后仍可查看。之后，如果你输入了新的用户内容并且新的回答成功保存，前一个回答只保留当时采用的版本；如果生成失败、取消，或只是继续生成而没有新的用户输入，已有候选会保留。切换正文中间的候选不会删除后面的段落，切换后请顺手检查衔接。

## 流式输出和取消

打开“设置”，在“生成”下勾选“流式输出”。它默认关闭，并保存在当前浏览器的显示偏好里。

- 开启后，正文生成会逐步显示临时文字。
- 临时文字出现时会提示“正在逐步生成，尚未写入正文”。
- 点“取消生成”后，生成草稿不会写入书目；页面会暂时保留文字供你选择和复制。
- 生成失败也不会把不完整的文字写入正文。开始另一轮生成或重新载入页面后，这个临时预览会被替换或清除。
- 梗概生成需要完整的结构化结果，不走正文的流式显示。

取消只能阻止 Story Room 应用迟到的结果落入正文；已经发送到你配置的模型服务的请求，是否被该服务记录或继续处理由服务端决定。

## 选择前文和保存梗概

“选择前文”让你选择当前小节之前的章节小节，并显示因目录移动而暂时不可用的既有引用。它把“选择要加载什么”和“确认写入设置”分成两步，避免你只是展开查看就改变生成上下文：

1. 勾选需要参考的前文。点击小节标题可以展开或收起它的梗概。
2. 如果还没有梗概，可以在“填写这一节的梗概…”里手写；也可以点“生成该节梗概”。AI 生成的文字先放在编辑框草稿里，确认保存前不会写入书目。
3. 检查选择后，点“保存并加载梗概”，再在确认框中确认。没有选择时，确认会取消当前小节的前文引用，但前文原文和已有梗概仍保留。
4. 有未保存改动的前文名称下会显示红字“此加载修改尚未保存”，保存成功后消失。点击抽屉外的空白处或关闭按钮即可退出；待确认的勾选和梗概修改不会生效，但会留在本次页面会话中，重新打开或切回该小节时可以继续编辑。

这份草稿还没有写入书目，不会改变本轮上下文或令牌数，也不会跨页面重新加载保留。离开页面时，尚未确认的修改会纳入未保存提醒。因移动而暂时不可用的引用会单独标明；你可以保留它，也可以明确取消勾选，确认时不会悄悄丢掉这些引用。

已保存的梗概会作为选中前文的摘要引用参与后续生成，而不是自动加载整段前文原文。梗概在内部以结构化小节梗概保存，并有当前版本和上一份快照；正文修改后，旧梗概可能变成过期状态，需要重新检查或生成。

正文页顶部的“本轮上下文概览”可以查看本次请求的大致模型服务、模型、字数/token 预算，以及哪些资料被纳入和原因。它是帮助你检查选择的摘要，不显示模型服务原始消息，也不显示隐藏的模型推理。

## 设置模型服务

点“设置”进入“模型连接”。先选择“新连接方案”，填写：

- “方案名称”
- “API Key”
- “URL”
- “模型 ID”
- “最大上下文”和“最大输出”

### OpenAI 兼容模型服务

- 选择你信任的 OpenAI 兼容模型服务。实际生成会把当前上下文计划选中的材料发送到该端点。

点“测试”只检查 `/models` 是否可达，以及返回模型列表时是否包含填写的模型 ID；测试成功不代表 `/chat/completions` 一定接受 Story Room 的生成参数。

密钥以明文保存在本地服务一侧的独立模型配置文件中，与书目分开。只有在信任目标服务时才输入密钥，不要写进书稿、JSON 备份或问题报告。

## 显示和阅读

“设置”里的显示项会保存在当前浏览器：

- “皮肤”：蓝雪、粉漫、灰度、紫雅。
- “全局字体”：无衬线或霞鹜文楷。
- “字号大小”：用加减按钮调整；移动宽度下正文会保持适合阅读的最小字号。

打开小节即可按连续正文阅读。需要交给其他阅读器时，在书架点“导出当前书目”选择 EPUB；需要继续改稿时可选 Markdown；只想留下最兼容的文字可选 TXT。需要保留完整编辑状态时，请选 JSON 完整备份。

## 自动保存、冲突和恢复

正文、块编辑、候选切换、书籍资料、加载范围和梗概要确认都会走同一套书目保存管线；正常修改会自动保存完整书目。

在本地服务模式，如果另一个页面先保存了同一本书，页面会提示“这本书已在其他页面更新；当前本地内容仍保留，可导出 JSON 备份或重新载入当前书目”。此时：

1. 先另行保留尚未发送或确认的编辑框文字，它们不一定在书目备份中。若当前书目改动要保留，再点“导出当前书目”选择 JSON 完整备份。
2. 确认备份后，点“重新载入当前书目”，读取最新已保存版本。
3. Story Room 不会自动合并两边的正文；请根据备份手动决定采用哪一部分。

本地服务模式的保存有事务日志和快照，用于处理进程中断；这不等于磁盘备份，也不能覆盖两个独立主机进程同时操作同一数据目录的情况。重要作品仍应另存 JSON 或其他外部备份。

## 当前 Alpha 的边界

- 目前没有云端存储、账号同步、多用户协作、RAG、向量嵌入或桌面封装。
- 应用不会武断限制正文、API 请求、模型服务响应、梗概项目或候选数量；保存仍会传输并校验完整书目，大书会需要更多内存和 I/O，模型服务自身的上下文和输出限制仍然有效。
- 上下文 token 估算用于提示，不会代替模型服务的实际限制，也不会因为估算值略超就自动阻止发送。
- 连接测试只验证 `/models` 的连通和模型列表匹配，不是完整生成兼容性验证。

更多数据边界和问题报告方式见 [`SECURITY.md`](../SECURITY.md)、[`PRIVACY.md`](../PRIVACY.md) 和 [`THREAT_MODEL.md`](THREAT_MODEL.md)。如果需要让 AI 代理解释功能或维护仓库，可以从 [AGENT_GUIDE.zh-CN.md](AGENT_GUIDE.zh-CN.md) 开始。
